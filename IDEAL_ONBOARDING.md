# Plaid Connector — идеальный первый запуск (целевая картина)

Источник методологии: `Docs/session-notes/ONBOARDING_FIRST_LAUNCH_STANDARD.md`.
Целевой пользователь: fintech-продукт/финансовый аналитик, подключающий Plaid
для доступа к банковским данным (см. `POST_CONNECT_EXPERIENCE.md`).

## 1. Credential type
Multi-secret по окружению: `client_id` (общий) + `sandbox_secret`/`development_secret`/
`production_secret` (разные по environment). Это РЕДКИЙ случай: у пользователя обычно
есть не все три сразу — только Sandbox на старте, Production выдаётся Plaid после review.

## 2. Идеальный флоу
1. **Первое открытие** — сайдбар: `Empty` с объяснением ролей client_id/secret и
   прямой ссылкой на Plaid Dashboard > Keys.
2. **Форма подключения** — идеально: три явно подписанных поля (client_id,
   sandbox_secret, production_secret), с явной меткой у каждого поля "заполните хотя
   бы одно окружение", а НЕ требование все три сразу — частая ошибка в чужих
   интеграциях, где Sandbox-пользователя вынуждают вводить Production-ключ, которого
   у него физически ещё нет.
3. **Переключатель активного окружения** — идеально: после подключения видимый
   Sandbox/Production toggle в шапке (аналог Live/Test у Stripe), с явным
   предупреждением при первом переключении в Production: "это реальные банковские
   данные конечных пользователей — включить логирование запросов?".
4. **Plaid Link flow** — идеально: т.к. реальное подключение банковского счёта конечным
   пользователем идёт через Plaid Link (отдельный клиентский виджет, не наш API-ключ),
   наш экран должен явно объяснить эту разницу: "это — ключ ВАШЕГО приложения к Plaid.
   Чтобы подключить банковский счёт клиента, используйте Plaid Link на своей стороне,
   мы подхватим item_id/access_token, который вы туда передадите" — inline `Alert(info)`.
5. **Multi-item список** — идеально: `DataTable` по всем подключенным `item_id`
   (=банковские подключения конечных пользователей) с институтом, статусом (good/
   error/pending_reauth), последним sync — не единственный "аккаунт", а список из
   потенциально сотен банковских связей.
6. **Ошибка ITEM_LOGIN_REQUIRED** — идеально: конкретный алерт "конечному пользователю
   нужно повторно пройти Plaid Link для реавторизации" (не общий "ошибка подключения") —
   это специфичный для Plaid код возврата, который наша таксономия §4 стандарта пока
   не называет явно; нужно расширить таксономию под multi-tenant коннекторы (Plaid,
   любой BaaS-агрегатор) отдельным классом "конечный пользователь должен переавторизоваться".
