# Plaid Connector — что видит и чем управляет пользователь после подключения

## 1. Целевой пользователь
Fintech-продукт/финансовый аналитик, использующий Plaid для доступа к банковским данным
конечных пользователей (баланс, транзакции, верификация счёта) через единый API вместо
интеграции с каждым банком по отдельности.

## 2. Момент истины после подключения
Сразу после `connect_plaid` (или после того, как конечный пользователь прошёл Link-флоу) —
`get_accounts`: список привязанных банковских счетов с их актуальным балансом.

## 3. Что пользователь видит
- Привязанные счета (checking/savings/credit) с балансом — `get_accounts`,
  `get_balance`.
- Историю транзакций по счёту с категоризацией — `get_transactions`.
- Верификацию личности владельца счёта (identity match) — `get_identity`.
- Данные о доходах, если пользователь их предоставил (income verification) —
  `get_income`.
- Статус связи (item) — не отозвал ли пользователь доступ, требуется ли повторная
  аутентификация — `get_item_status`.
- Информацию об учреждении (банке) — `get_institution`.

## 4. Чем пользователь может управлять
- Инициировать создание Link-токена для нового подключения счёта конечным пользователем —
  `create_link_token`.
- Обновлять/восстанавливать соединение (item), если банк потребовал повторный логин, —
  `create_update_link_token`.
- Удалять привязку счёта (item) по запросу пользователя — `remove_item`.
- Запрашивать перевод денег между счетами (если используется Plaid Transfer) —
  `create_transfer`.
- Настраивать webhook для получения обновлений о транзакциях в реальном времени —
  `set_webhook`.

## 5. "Вау"-момент для демо потенциальному клиенту
"Смотри — говорю Webbee: 'привязан ли у этого клиента банковский счёт и какой у него
баланс?'. Она находит через `get_accounts` реальные данные (в тестовом/sandbox-режиме),
а я показываю, как через `get_transactions` тут же строится анализ расходов."

## 6. Что делает это "заточенным под него"
Работает с ЛЮБЫМ из тысяч поддерживаемых Plaid банков-партнёров данного региона —
Webbee не привязана к одному банку, а к тому, что реально выбрал конечный пользователь.
